# HTML в документации Project Hub

Markdown и HTML используют одну модель статей, аудитории и тематических папок.
`audience=developer` открывает «Разработка приложения»; `section` задаёт путь
вложенных папок через `/`. Формат не создаёт отдельный раздел.

HTML импортируется через существующие `import-preview`, `import-read` и
`import-apply`. Оригиналы не меняются. Запись документа содержит `format=html`
и `htmlBundle` с entry и проверенным manifest файлов, хешей и размеров.
Байты находятся в существующем immutable blob store. Один файл ограничен
4 MB, комплект — 32 MB и 400 файлами. Импорт принимает до 50 исходных страниц.

Снимок сохраняет локальные ссылки HTML, CSS url/import, обычные script/src,
изображения и распознаваемые статические ссылки JavaScript. Защищённые каталоги,
выходы из корня, symlinks/junctions и отсутствующие зависимости не импортируются.
Неполнота указывается явно. Динамически вычисляемые пути не гарантируются.
Внешние ресурсы не скачиваются и не выполняются. Fetch, ES modules, workers,
host bridges приложения и произвольные сетевые обращения в просмотре не
поддерживаются. CSS, обычные локальные/inline скрипты и встроенные данные
самостоятельных прототипов сохраняются.

По умолчанию статья показывает изолированный iframe на всю ширину основной
области, включая широкие экраны. Высота окна просмотра зависит только от
размера экрана, а не от высоты HTML. Прокрутка и ограничения панелей остаются
такими, как их определяет исходный макет. Автоматического измерения высоты,
внедрённого адаптера и переписывания CSS страницы нет: вёрстка, зависящая от
высоты viewport, не вызывает цикл роста окна Hub. Для просмотра на всю
страницу используется «Открыть отдельно».
Контейнер использует тёмный фон. Для HTML без собственной цветовой схемы копия
для встроенного просмотра получает стандартные метаданные `color-scheme=dark`:
браузер рисует свой фон и элементы по умолчанию в тёмной теме. Явно заданные
цвета и цветовая схема страницы сохраняются. Отдельная страница, сохранённый
снимок и ресурсы остаются исходными. Компактное дерево считает статьи во всех
вложенных папках.
Разделитель меняет его ширину перетаскиванием или клавишами
стрелок, Home/End; выбранная ширина сохраняется для проекта в браузере.
Кнопка возле поиска полностью скрывает дерево, освобождая его место.
«Открыть отдельно» открывает тот же HTML без
оболочки Hub. URL содержит проект, knowledge revision, ID документа и путь
файла; сервер читает только manifest выбранной исторической версии. CSP sandbox
allow-scripts не разрешает same-origin, внешние скрипты, формы, workers и
сетевые запросы. CORS не включается. Исходный HTML никогда не вставляется
в DOM портала. Текст Markdown сохраняет прежний читательский режим.

`import-read(field=source|html)` возвращает исходник страницы частями.
`field=diff` показывает изменение исходника и manifest зависимостей.
Изменение только CSS/JS тоже требует выбранного обновления. Классификация,
название и ссылки автора сохраняются при повторном импорте.
`import-apply(metadata={documentId: {...}})` позволяет сразу задать проверенные
title, description, audience, section, type, status, documentDate, dateBasis,
versionLabel, versionGroup, entityRefs и documentRefs.

Сортировка страниц в тематической папке использует documentDate от новых к
старым, затем название. Основание даты показывается отдельно; первый коммит
не объявляется датой создания. `historical` требует основания устаревания,
`draft` — уместен для предложений и не реализованных макетов. Runtime и test
resources объясняются в описании. Версии одной темы объединяются versionGroup
и ссылками documentRefs; история knowledge revision остаётся отдельной.

История, task sources и hub_memory читают сохранённый исходник HTML независимо
от наличия файлов проекта. Внутренний ZIP экспорт содержит полный комплект с
исходной относительной структурой; backup сохраняет текущие и исторические
blobs. Публичный экспорт исполняемых HTML запрещён.
