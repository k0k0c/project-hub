# Основная задача и оценка готовности

Основная задача выбирается сервером для каждого проекта. Явное назначение агентом
по просьбе пользователя имеет приоритет. Иначе рассматриваются задачи с активной
работой: при наличии оценки оставшихся часов выбирается крупнейшая, а без оценки —
задача с наиболее свежей активной работой. Завершённые и отменённые задачи исключены.
Если кандидатов нет, карточка сообщает об отсутствии основной задачи.

Оценка хранит диапазон готовности 0–100%, диапазон оставшихся часов работы агента,
степень уверенности и краткое обоснование. Сервер фиксирует дату пересмотра и автора.
Часы — не срок доставки и не прошедшее время. Процент не вычисляется по количеству
закрытых этапов: их объём различается. Старые оценки без даты явно требуют пересмотра.

## Команды агента

Прочитать `hub_plan(task)` и использовать возвращённую revision в expected:

```text
hub_plan(task, expected=revision, primary=true)
hub_plan(task, expected=revision, primary=false)
hub_plan(task, expected=revision, estimate={
  percentLow:55, percentHigh:60, hoursLow:15, hoursHigh:25,
  confidence:"Средняя", note:"Что проверено и что осталось"
})
```

Это примеры контракта, не оценка конкретного проекта. Назначение и оценку можно
передать в одном вызове. Изменение этапа или решение передаются отдельным вызовом.
Часы необязательны, но передаются парой; отсутствие пары очищает прежний ориентир.
Дата и автор не принимаются от клиента. Прежние события не перезаписываются.
Устаревшая revision отклоняется; точный повтор успешного запроса идемпотентен.
Перенос задачи не переносит явное назначение основной в другой проект.

## Обновление без фоновой модели

Агент пересматривает оценку после крупного результата/изменения объёма и на ближайшем
контрольном отчёте после 60 минут наблюдаемой активной работы. Обычные ответы
hub_context, hub_begin и hub_report содержат компактный progressHint; hub_plan
показывает оценку и её актуальность даже при сокращённом плане. Сервер не запускает
модель, не увеличивает проценты по времени и не требует постоянного опроса.
Если диапазон не изменился, повторная обоснованная оценка обновляет дату.
Главный исполнитель отвечает за общую оценку; подагенты передают ему результаты.

Проценты и оставшиеся часы показаны на основной карточке, карточках в обзоре/списке
и в общей шапке подробностей задачи. Этапы сохраняют прежнее отображение статусов.
Старые оценки других проектов не пересчитываются автоматически без проверки их плана.

## Сводка текущей работы

Карточка «Текущая работа» независима от основной задачи. Она группирует все
подтверждённые активные работы подключённых чатов по задачам и этапам: ссылка на
задачу, ссылка на пункт плана и краткое описание работы. Учитываются одновременно
активные запись работы и состояние её чата; ожидание и завершение исключаются.
Историческое событие начала шага само по себе не подтверждает текущую работу.
При большом числе пунктов список прокручивается внутри компактной карточки.

Рядом со статусом плана показывается независимая активность агента. Задача может
оставаться «В работе», пока её агент остановлен. Активность определяется по записям
работы и последним lifecycle-событиям чатов; отсутствующие наблюдения обозначаются
как неизвестные. Для этапа учитываются только работы этого этапа. Stop/Interrupt
не завершают задачу и не освобождают резервирования. Отдельный фоновой запуск модели
не нужен. Потерянное событие Stop нельзя надёжно отличить от долгого обдумывания:
произвольный тайм-аут не используется для объявления агента остановленным.
