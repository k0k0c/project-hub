# Неблокирующая политика Project Hub

Project Hub хранит историю проекта, результаты и сведения для согласования работы. У каждой задачи есть видимый этап и результат. Начало содержательной работы регистрируется через `hub_begin`, а результат — через `hub_report`. Для существенного продолжения агент читает план и обновляет примерную оценку готовности. Если оставшееся время неизвестно, он объясняет неопределённость.

Агент использует собственную проверенную identity. После `identity_missing` можно повторно привязать ту же собственную identity и проверить проект. ID родителя не становится ID подагента из-за наследования переменной окружения. Если привязка или запись недоступна, агент продолжает разрешённую работу и сообщает о пробеле учёта. Чужие отчёты и история остаются у их владельцев.

## Совместная работа

Основной агент распределяет задания, согласует пересечения правок и общие сборки, принимает результаты и проверяет итог. Подагент связывает свою работу с родительской задачей и сохраняет результат под собственной identity, если подключение доступно. Основной агент сохраняет сводный результат интеграции.

Уведомления о пересечении ресурсов описывают заявленную область работы и свежесть наблюдения. Агент проверяет действительное пересечение и согласует изменения через доступные средства клиента. Сообщение Hub само по себе не разрешает писать в чужие файлы или отправлять сообщения другим чатам.

## Разрешения и наблюдения

Регистрация работы — учёт, а доступ к файлам определяется разрешениями клиента и операционной системы. Hub не выдаёт `permissionDecision` и не заменяет штатную проверку доступа. Отсутствие события Hub означает неизвестность, а не доказательство остановки, активности или успеха агента.

Совместимый обработчик явных edit tools может записывать `diagnostic.edit_without_write_work`, когда собственная MCP identity известна, но подходящей активной работы с этапом нет. Событие означает получение вызова; оно не доказывает успешную запись. Неизвестная identity, неизвестный путь и инструменты чтения не создают таких диагностик. Обработчики возвращают пустой ответ, а ошибки наблюдения не запрещают выполнение задачи.

Остановка сеанса и его закрытие являются наблюдениями. Задача или этап завершаются только после проверки условий и сохранения фактического результата. Запись решения не заменяет план этапов, а успешная запись в базу не означает Git-коммит или публикацию исходников.
