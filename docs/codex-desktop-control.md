# Управление чатами открытого Codex из Hub

Экспериментальный адаптер позволяет Hub создать чат в выбранном локальном проекте Codex, отправить в этот чат сообщение и проверить его присутствие в приложении. Для работы Codex должен оставаться запущенным. Вход агента в Hub по MCP и запросы самого Hub к сервису модели настраиваются отдельно.

Адаптер использует внутренний канал штатных инструментов приложения. Это не публичный API OpenAI: после обновления Codex совместимость может измениться. При несовпадении ожидаемых операций или формата ответа адаптер прекращает работу. Результат проверки возможностей общий для подключения приложения и относится к запущенному экземпляру и времени проверки. Проект определяет место создания тестового чата и сохраняется в истории попытки.

## Подключение

В чате Codex попросите агента подключить адаптер для нужного приложения Hub. Проекты задаются действующими привязками этого приложения на вкладке «Привязки проектов»; отдельного списка разрешённых папок у адаптера нет. Настройка должна выполняться из этого чата: Codex передаёт ему адрес своего канала и действительную идентичность вызывающего чата. Адаптер не ищет приватные каналы других процессов.

Для установки из исходников используется `scripts/codex_desktop_setup.py` с параметрами:

- `--hub-url` — адрес локальной установки Hub вида `http://127.0.0.1:PORT`;
- `--connection` — ID существующего активного подключения Codex;
- `--runtime-dir` — отдельная папка состояния вне исходников и рабочих папок проектов.

Скрипт проверяет действующий чат Codex, запускает адаптер только на `127.0.0.1`, создаёт отдельный случайный ключ и сохраняет профиль и доступ в Hub. Ключ попадает в существующее приватное хранилище Hub; он не записывается в профиль, журнал адаптера, командную строку или исходники. Успешное сохранение не создаёт тестовый чат и не запускает проверку.

В настройках приложения Hub откройте «Чаты приложения», выберите привязку проекта и отдельно запустите проверку. Она создаёт чат и отправляет сообщение; запрос к модели может использовать ваш тариф. Папка выбранной привязки должна однозначно соответствовать локальному проекту Codex. Название проекта само по себе не используется для выбора.

Для нескольких проектов добавьте их привязки в Hub. Для каждой папки нужен локальный проект
Codex и действующая привязка Hub. Добавление и отключение привязки учитываются при следующем обращении без перезапуска адаптера и отдельного разрешения папки. Перед созданием и отправкой адаптер повторно проверяет привязку; недоступный Hub, отключённое приложение или изменённая привязка останавливают операцию. Это не меняет файловые разрешения самого Codex.

Выберите, где создать тестовый чат; переключение
проекта не меняет статусы возможностей приложения. Успешная проверка обмена не
выдаёт доступ к другим папкам и не проверяет их привязки. Две папки с похожими названиями не объединяются.
Отправка чата одного проекта в другой отклоняется.

Git не является условием работы с чатами: проектом может быть обычная папка без репозитория или с другой системой контроля версий. В некоторых версиях Codex публичный список проектов исключает запись при ошибке необязательных Git-метаданных. В этом случае адаптер использует подтверждённую принадлежность существующего нативного чата той же папке и проекту. Он не изменяет владельца папки и не добавляет исключений `safe.directory`.

Если Codex не вернул проект ни в списке проектов, ни среди недавних или закреплённых чатов, адаптер сообщает о недоступных сведениях каталога. Это не доказывает отсутствие проекта. Для пустого проекта, скрытого самим Codex из списка, имеющийся интерфейс пока не позволяет независимо получить его папку; нужен корректный каталог со стороны приложения. Адаптер не угадывает проект по названию и не подменяет его другим.

## Что подтверждает проверка

Последний результат показан рядом с кнопкой проверки. При отказе указаны причина и операция, на которой он произошёл: соединение, получение возможностей, создание чата или отправка сообщения. Подробности сохраняются в журнале. Различайте недоступность Hub, отключённую или изменённую привязку, ошибку отдельного ключа адаптера, недоступные сведения Codex и истечение срока ожидания. Текст стороннего сервера и секреты в сообщение об ошибке не копируются.

Адаптер получает настоящий ID из `create_thread`, затем независимо запрашивает каталог `list_threads` приложения. Проверяются ID, локальный хост, папка и принадлежность выбранному проекту. Каталог принимает до 50 записей за запрос; новый чат проверяется среди недавних и закреплённых. Если он не найден, присутствие остаётся неподтверждённым. Для продолжения Hub показывает сохранённые связи с задачей или этапом, в том числе связанные чаты, созданные вне адаптера. Перед отправкой текущий проект, привязка и доступность выбранного чата проверяются снова; одного названия или старой записи недостаточно.

Каталог может обновляться с задержкой. Адаптер ожидает появления записи до 18 секунд, повторяя только читающий запрос. На создание в профиле задан тайм-аут 30 секунд; команда создания при таком ожидании не повторяется.

Чтение содержимого через `read_thread` — отдельная операция. Сразу после создания чат уже может быть виден в приложении, пока его история ещё недоступна для чтения. Это состояние не считается отсутствием чата. При подключении адаптер использует `read_thread` для проверки действительного вызывающего чата, который уже существует в Codex.

Подтверждение присутствия в каталоге приложения не означает, что окно переключилось на этот чат. Ссылка `codex://threads/...` позволяет открыть его отдельно. Принятие сообщения приложением и ответ агента также различаются: стандартная проверка Hub ожидает отдельный ответ из созданного чата с одноразовым кодом проверки.

## Запуск задачи из Hub

Откройте карточку задачи или её этапа. В блоке «Запустить задачу» выберите приложение и папку проекта. В списке доступны только активные привязки этого проекта с настроенным интерфейсом управления. Адаптер использует эти же привязки.

Выберите создание нового чата либо «Продолжить чат». Для продолжения выберите чат по его названию. В списке есть чат создания задачи, чат создания выбранного этапа и другие связанные чаты, если приложение передало Hub их идентификаторы. Чат задачи доступен и для её этапов; чат отдельного этапа относится к этому этапу. Список также включает ранее подтверждённые запуски через Hub. Перед отправкой адаптер проверяет выбранный чат, его рабочую папку и действующую привязку проекта. При необходимости добавьте инструкцию и нажмите «Запустить». Отправка использует модель и права, настроенные в приложении. Настройки запросов самого Hub к модели этот запуск не определяют.

Hub передаёт существующую задачу, выбранный этап, проект и ревизию привязки. Агент сначала читает запрос через `hub_launch` и подтверждает фактический проект и ID чата. Затем он учитывает работу в этой же задаче, сохраняет отчёт и возвращает ссылку на него в запрос запуска. При изменении задачи до подтверждения, привязки или маршрута управления запрос отклоняется: сохранённая история остаётся доступной для разбора.

В истории запуска отдельно показаны три факта: интерфейс приложения принял команду, агент подтвердил получение задания, результат сохранён в Hub. Принятие команды не означает начала или завершения работы. Результат содержит текст отчёта и его источники; чат можно открыть отдельной ссылкой. Ошибка выполнения также сохраняется в истории.

Продолжать можно чат, сохранённый для той же задачи или этапа и проверенный в текущем проекте Codex с действующей привязкой. Это может быть завершённый или завершившийся ошибкой запуск либо связанный чат, который не создавался адаптером. Во время активного запуска или при неизвестном исходе отправки продолжение блокируется. Произвольный чат из приложения не подставляется автоматически.

Если в старой записи сохранился идентификатор исходного чата, Hub может подтвердить его через каталог приложения. Когда идентификатор неизвестен, одного названия или времени создания недостаточно: такой чат остаётся в истории без возможности продолжения. Создайте новый чат через Hub или передайте сведения об исходном чате из самого приложения. Изменённая привязка не наследует право отправки в чаты прежнего проекта.

Если ответ Hub потерян, используйте «Повторить тот же запрос». Этот повтор читает результат сохранённого запроса и не создаёт второй чат. До выяснения результата форма не отправляет другое задание. Неизвестный исход внешнего вызова требует проверки приложения; автоматического повторного создания или отправки нет.

Если Hub вернул известный отказ до отправки — например, интерфейс не настроен
или выбранный чат занят — исправьте указанную причину и отправьте задание снова.
Такой отказ не считается потерянным ответом. При статусе «Результат отправки
неизвестен» новое задание в форме этого этапа заблокировано. Поздний ACK агента
может подтвердить исход; Hub продолжает читать состояние. Точный повтор запроса
Hub не запрашивает повтор операции у адаптера. Автоматического восстановления
неизвестной внешней операции сейчас нет.

## Повторное подключение и сбои

При закрытии нативного канала Codex адаптер закрывает свой HTTP listener. Hub сохраняет настройки и историю, поэтому сохранённый адрес сам по себе не подтверждает текущую доступность. После закрытия или обновления Codex запустите настройку из нового чата и выполните отдельную проверку. Это не включает автоматический запуск Codex или адаптера при загрузке компьютера.

Перед созданием чата и отправкой адаптер сохраняет запись операции. Повтор того же запроса возвращает сохранённый результат. Изменённое содержимое с тем же ID отклоняется. Если связь оборвалась после отправки команды и результат неизвестен, запрос не повторяется автоматически: сначала проверьте чаты в приложении и записи состояния. Журнал не содержит текста сообщений или ключей.

Настройка сериализована системной блокировкой. После аварийного завершения она удаляет оставшийся lock-файл только когда прежний процесс точно завершён; записи операций сохраняются. Если процесс существует либо его состояние не удалось установить, новое подключение не запускается. Состояние разных экземпляров приложения хранится отдельно; чаты старого экземпляра не принимаются новым адаптером автоматически.

Различайте три ожидания: появление чата в каталоге приложения, ответ интерфейса
управления и обратный ответ агента. Проверка обмена ждёт обратный ответ до 90 секунд
с начала попытки. Тайм-аут не означает, что чат не был создан. В журнале остаются
подтверждённые факты и время попытки. Поздний ответ после истечения срока отклоняется.
Изменение привязки во время проверки также отменяет её подтверждение.

Запросы **Hub → сервис модели** используют отдельное подключение и могут работать
после выхода из Codex. Требуется работающий сервер Hub и действительная авторизация
сервиса. [Проверка после выхода из приложения](mcp-project-connections.md#проверка-запросов-к-модели-после-выхода-из-codex)
выполняется из обычного браузера; проверка чатов Codex в этом состоянии недоступна.

## Граница реализации

Адаптер не меняет конфигурацию и базу Codex, не подключается к stdin чужого процесса и не запускает отдельный агентский App Server. Он не передаёт произвольные инструменты приложения через HTTP, не выбирает модель, не создаёт worktree и не добавляет доступ к другим папкам. Нативные ошибки и запросы, которые приложение не принимает, не превращаются в успех.

Документированный [Codex App Server](https://learn.chatgpt.com/docs/app-server) остаётся отдельным JSON-RPC интерфейсом для собственных клиентов. Его запуск через `stdio` не создаёт внешний сокет; настройка daemon не присоединяет Hub автоматически к уже открытому Desktop.
