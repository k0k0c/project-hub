# MCP-подключение агента к проектам

Project Hub подключается к агенту через Streamable HTTP MCP. Плагин не требуется.
Поддерживаемый клиент работает с проектом или репозиторием, предоставляет агенту
его контекст и загружает постоянные инструкции проекта. Настройка подключения
выполняется один раз; привязки отдельных проектов появляются при начале работы.

В этой интеграции три независимых направления:

- **Агент → Hub:** инструменты MCP для чтения и изменения данных Hub. Приглашение
  используется для регистрации доступа по HTTP и настройки MCP в приложении;
  сама ссылка ещё не подтверждает подключение инструментов.
- **Hub → приложение:** создание чата и отправка сообщения через отдельно
  настроенный интерфейс управления. Для текущего Codex доступен
  [экспериментальный локальный адаптер](codex-desktop-control.md).
- **Hub → сервис модели:** прямые запросы с API-ключом или авторизацией ChatGPT.
  Codex и его адаптер для этого не нужны; Hub должен оставаться запущенным.

Приглашение регистрирует подключение приложения по HTTP и выдаёт отдельный
токен доступа к Hub. Затем клиент сохраняет адрес `/mcp` и этот токен в своих
настройках MCP. Токен относится к зарегистрированному подключению, а выбранная
модель и отдельные чаты могут меняться. Для каждого нового подключения создайте
новое приглашение; использованная ссылка не регистрирует другое приложение.
Клиент должен поддерживать Streamable HTTP MCP с токеном доступа. Если он не
умеет самостоятельно сохранять настройки или правила, потребуется ручная настройка.
Отключение доступа в Hub отзывает токен этого подключения.

## Мастер первого подключения

При первом открытии портала автоматически появляется **Мастер подключения**.
Позже откройте **Настройки → Общие → Мастер подключения**. Закрытие окна
сохраняет текущий шаг; после завершения мастер можно запустить снова, чтобы
проверить подключение или добавить ещё одно приложение. Прогресс общий для
этой установки Hub, поэтому повторное открытие браузера не запускает мастер
заново автоматически.

Выберите **Codex** или **Другое приложение**, создайте приглашение и передайте
скопированный текст в чат нужного проекта. При настройке из такого чата агент
создаёт или находит проект и сохраняет его привязку. Мастер проверяет доступ
к инструментам, сохранение постоянных правил и появление проекта отдельно.
Уже найденный проект не требуется создавать повторно. Если приложение связано
с несколькими проектами, выберите нужный.

Для другого приложения требуется поддержка MCP по HTTP. Готовый локальный
адаптер управления чатами в этой версии доступен для Codex. Его настройка
и явная проверка тестовым чатом предлагаются отдельным шагом.

Вход через ChatGPT и подключение API-ключа необязательны: это способы выполнять
запросы к модели из самого Hub. Сохранение подключения не отправляет запрос
к модели. Кнопка проверки отправляет отдельный запрос по лимиту подписки или
тарифу сервиса. Секретный ключ не записывается в прогресс мастера.

Для исследований без среды разработки можно выбрать **Проект вручную** на
первой странице. Ручное добавление также доступно, если проект из чата ещё
не определён. Папка исходников при этом необязательна.

Каждый шаг занимает одну компактную страницу. Справочная ссылка внизу окна
открывает соответствующий раздел настроек в новой вкладке. Страница входа
ChatGPT также открывается отдельно, сохраняя текущий шаг мастера.

При повторном запуске существующие подключения и проекты сохраняются. Для
ещё одного приложения создаётся новое приглашение: уже использованная ссылка
не подходит. Если доступ выбранного приложения отозван, действие
**Восстановить доступ** выдаёт отдельное приглашение для восстановления
его прежнего подключения.

## Адрес и восстановление связи

Клиент сохраняет полный адрес HTTP MCP, включая порт и путь `/mcp`. Доступ к
инструментам появляется после проверки токена и получения каталога команд.
Приглашение передаёт адрес действующего сервера; само знание номера порта
не предоставляет доступ и не устанавливает инструменты в произвольном приложении.

`localhost` — стандартное имя локального компьютера. Hub слушает локальные
IPv4- и IPv6-адреса, без публикации порта во внешней сети. Настройка отдельного
DNS не требуется: имя определяет компьютер, а порт остаётся частью адреса.

При первом запуске используется предпочтительный порт из конфигурации установки.
Если он занят, Hub может выбрать свободный и сохраняет фактический порт рядом
с конфигурацией в `launcher-runtime.json`. Последующие запуски сохраняют этот
адрес. Занятый сохранённый порт приводит к ошибке запуска; Hub не переключает
подключённых клиентов на случайный порт. Изменение адреса требует согласованного
обновления настройки MCP в клиентах. Протокол не предусматривает передачу нового
адреса клиенту, который уже потерял связь со старым.

Остановка Hub не отзывает токен, не удаляет правила и не меняет привязки проектов.
После запуска по прежнему адресу клиент может снова инициализировать MCP и получить
каталог. Если клиент сохранил ошибку первоначального подключения, обновите MCP в
его настройках. Codex предоставляет документированную команду управления
`config/mcpServer/reload`; она выполняется через интерфейс уже работающего клиента.
Отдельно запущенная проверка не перезагружает MCP в открытом приложении и не
подтверждает загрузку инструментов текущим чатом. Новое приглашение для восстановления
транспортного соединения не требуется. Не повторяйте запись задачи после потери
ответа, пока не проверено, была ли она применена.

На Windows запуск фонового сервера из другого приложения может наследовать
ограничение времени жизни этого приложения. Запуск из исходников через
`python scripts/hub_source.py --mode work` передаёт создание супервизора оболочке
рабочего стола Windows. Супервизор управляет сервером и его значком; закрытие
терминала или приложения, из которого выполнена команда, не останавливает Hub.
Остановка выполняется через значок сервера или команду запуска с `--stop`.

Программа проверяет пользователя рабочего стола, родительский процесс и ограничения
нового супервизора. Если независимость подтвердить нельзя, запуск завершается
явной ошибкой. Для запуска требуются обычный пользовательский процесс и доступный
рабочий стол Explorer. Ограничения среды выполнения и права доступа не отключаются;
служба, задание планировщика и изменения реестра не создаются.
Операции запуска и остановки выполняются в одном контексте рабочего стола:
отдельные копии файлов AppData, которые Windows может показывать приложениям
из Microsoft Store, не используются для управления другим экземпляром сервера.
Диагностика сохраняет родительский PID, свойства Windows Job,
последнюю фазу supervisor и признак завершения. Если запись о завершении отсутствует,
причина отмечается как неизвестная, без предположения о сбое VPN или приложения.

Различайте номер порта и код ошибки Windows: `10061` означает отказ подключения,
`10013` — запрет доступа к сокету. Ошибка запуска проверяющего процесса также
отличается от тайм-аута MCP. Увеличение времени ожидания не исправляет эти причины.

Основание: [транспорт MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports),
[локальное имя localhost](https://www.rfc-editor.org/rfc/rfc6761.html#section-6.3),
[интерфейс управления Codex](https://learn.chatgpt.com/docs/app-server).
Штатный запуск через рабочий стол описан в
[примере Microsoft Execute in Explorer](https://learn.microsoft.com/en-us/windows/win32/shell/samples-execinexplorer).

## Общие и проектные инструкции

Приглашение возвращает контракт версии 5 и `instructionBundle`. Комплект содержит
`workflow.md` с полными правилами, `user-additions.md` с дополнениями из настроек
Hub, `bootstrap.md` с коротким общим правилом и `api-reference.md` со схемами команд.
`manifest.json` фиксирует версии,
размеры и SHA-256 компонентов, а также ревизию всего комплекта. Ревизии сравниваются
на равенство: контрольная сумма не является порядковым номером версии.

Команда `hub-cli onboarding` сохраняет отдельный локальный снимок вне репозитория.
Для Codex короткий блок добавляется в пользовательский `AGENTS.md` в `CODEX_HOME`
или в действующий `AGENTS.override.md`. Личные правила и другие подключения
сохраняются. Правило требует читать оба полных файла в начале каждого чата и
после сжатия контекста. Сохранение файлов и фактическая загрузка новым чатом —
разные результаты проверки. Произвольный Markdown-файл сам по себе не становится
постоянной инструкцией клиента.

Для Cursor сохраняется комплект и возвращается текст для штатных User Rules;
автоматическое редактирование глобальных User Rules через недокументированный
файл не используется. Проектные правила Cursor поддерживаются через Always Apply
в `.cursor/rules`. Другие клиенты получают текст для своего штатного механизма;
автоматическую установку нельзя считать выполненной без соответствующего адаптера.
Обычные разрешения среды действуют при всех изменениях файлов. Подключение не
отключает запросы разрешений и не требует отдельного повторного подтверждения
уже разрешённой установки управляемых правил.

В начале чата агент вызывает `hub_instructions(action="manifest", session=...)`.
При изменении версии, пропаже или повреждении файла он получает `action="read"`,
проверяет комплект и устанавливает новый снимок. `onboarding --refresh --session`
получает текущий комплект через API того же MCP-контракта. Команда сначала
возвращает конкретный preview; `--apply --expected-preview` применяет именно его.
Обновление сначала сохраняет полный снимок, затем атомарно меняет короткое правило.
Опубликованные снимки не переписываются при ремонте. Ответы `hub_context`,
`hub_begin` и `hub_report` также содержат текущий манифест. Без связи с Hub остаётся
последняя проверенная версия. Файлы не гарантируют соблюдение правил моделью:
загрузку и поведение после сжатия проверяют отдельно в самом клиенте.

## Привязка проекта

Общее правило действует и в новых проектах без проектной инструкции Hub. Агент
определяет текущую область `{kind, root?, nativeRef?}` и вызывает
`hub_project_bindings(action="resolve", scope=..., requestId=..., session=...)`.
Для локального подключения `root` — существующий каталог на машине Hub; это
явная граница текущей локальной реализации. Клиентский `nativeRef` может храниться
без каталога, но требует выбранного канонического ID Hub. Удалённые клиентские
пути не выдаются за серверные рабочие каталоги.

Hub сопоставляет зарегистрированные корни. При единственном совпадении возвращает
существующий ID. Новый корень регистрируется автоматически вместе с привязкой.
При нескольких совпадениях требуется выбор ID; имя проекта не служит доказательством
идентичности. Стабильный requestId предотвращает повторное создание после потери
ответа. Агент сообщает о создании привязки и сохраняет небольшой проектный блок
через `hub-cli project-rule`. Полные общие инструкции в этот блок не копируются.

Область, ID Hub, ID привязки и ревизия сохраняются в Hub и в проектном правиле.
В начале чата `hub_context` принимает `project`, `bindingId`, `bindingRevision`
и `projectScope`, определённую из фактического текущего проекта клиента. Затем
тот же ID и ревизия сопровождают запросы; повторное чтение всего каталога не нужно.
Сведения о нативной области остаются заявлением клиента, а не подтверждённой
идентичностью процесса. Запросы к исходникам требуют зарегистрированного workspace.

MCP поддерживает list/read/history/workspaces, resolve/create, update/relocate/resume, verify, repair и
unbind. Изменения используют `expectedRevision` и requestId. verify фиксирует
отчёт клиента о сохранении правила; он не доказывает загрузку в новом чате.
`workspaces` возвращает ID рабочих каталогов и ревизию проекта; `relocate`
перемещает регистрацию каталога и привязку с проверкой обеих ревизий.
Прерванный перенос блокирует работу и запуск по этой привязке. Hub сохраняет
исходные аргументы; read/list возвращают pendingRelocation, а resume повторяет
сохранённый запрос по его requestId. Продолжение доступно и в веб-интерфейсе.
Старая запись без аргументов требует отдельного согласования, а не угадывания.
Если изменение каталога было отклонено без записи, блокировка снимается.
Отвязка сохраняет историю и запрещает автоматическое восстановление этой области.
Агент удаляет только свой блок правила. Перепривязка и перемещение требуют ремонта
клиентского правила; задачи, работа и история не переносятся. После перепривязки
к другому проекту требуется новая сессия чата.

В разделе **Настройки → Агенты и подключения** есть три подраздела:

- **Приложения** — каталог подключений. Откройте приложение, чтобы увидеть
  состояние доступа, привязки проектов и диагностику. Доступ агента к Hub, управление
  чатами из Hub и сохранение инструкций показываются отдельно.
- **Запросы к моделям** — API-сервисы для прямого анализа из Hub. Сервис можно
  добавить, изменить, выбрать для запросов или удалить. Сохранённый ключ не
  показывается. Пустое поле ключа при редактировании сохраняет его, если адрес
  и протокол прежние; для другого адреса или протокола нужен новый ключ.
  Удаление выбранного сервиса отключает прямые запросы до явного выбора другого.
- **Правила работы** — общая инструкция агента и ваши дополнения. Сохранение
  дополнений в Hub не подтверждает их загрузку в приложении.

На вкладке **Привязки проектов** выбранного приложения можно включить учёт существующего
проекта Hub, запросить обновление его правила, открыть историю или отключить
автоматический учёт. Папка показана только для справки: используется основная
папка, зарегистрированная в Hub. Папки исходников и внешние ресурсы настраиваются
только в разделе **Проекты**. Настройки подключения не переназначают проект
приложения другому проекту Hub и не изменяют ресурсные папки.

Запрос обновления помечает правило для синхронизации. Hub не может напрямую
изменить файлы произвольного клиента: обновление выполняет агент при следующем
обращении. Недоступные клиенты остаются в состоянии ожидания. Отключение учёта
сохраняет задачи и историю; повторное включение требует явного действия.
Запуск задач и исследований выполняется в соответствующих рабочих разделах,
а не в настройках подключения.

### Направления связи и проверки

Настройки приложений относятся ко всей установке Hub, даже когда в основном меню
выбран отдельный проект. Число привязок показывает, сколько областей приложения
связано с проектами Hub; это не перечень индивидуальных разрешений доступа.

На вкладке **Доступ к Hub** показано направление **Агент → Hub**: агент вызывает
инструменты Hub. Последний запрос с действующим доступом подтверждает обращение
в этот момент. Он не подтверждает текущую работу агента, загрузку всех инструментов
или чтение правил новым чатом. Статус установки правил показывает отчёт клиента.

На вкладке **Чаты приложения** показаны отдельные функции: открытие существующего
чата из браузера, создание чата из Hub, отправка сообщения и подтверждение обмена.
Заявление клиента о возможности не означает, что серверу Hub доступен интерфейс
управления. Если приложение его не предоставило, это указано прямо. При наличии
интерфейса используются его документированные адрес и протокол — MCP через HTTP
или HTTP JSON — и отдельные учётные данные.

В этой версии готовый локальный адаптер управления чатами доступен для Codex.
Другому приложению нужен собственный совместимый интерфейс или адаптер.
Приглашение MCP настраивает доступ агента к Hub и не создаёт обратный интерфейс.

**Сохранить настройки** сохраняет адрес и ключ без обращения к приложению.
Обновление профиля клиентом также не запускает проверку. Для явной проверки
используйте **Создать тестовый чат и проверить обмен**: это действие создаёт
отдельный чат и отправляет диагностическое сообщение; приложение может выполнить
запрос к модели. Кнопка доступна после настройки совпадающего интерфейса с описанной
операцией создания чата. Несохранённые изменения нужно сначала сохранить.

Результаты разделены по фактам: API вернул идентификатор созданного чата, принял
сообщение, получен обратный запрос с совпавшим кодом и идентификатором. Наличие
ссылки на чат не подтверждает открытие окна приложения. При изменении профиля,
настроек или самой привязки, использованной в попытке, прежний результат помечается
как неактуальный. Статусы возможностей общие для подключения приложения.
Переключение проекта в форме проверки их не меняет: проект определяет место
создания тестового чата и сохраняется в журнале попытки. Адаптер Codex использует
активные привязки Hub: отдельный список папок и повторное разрешение при добавлении
проекта не нужны. Перед обращением проверяются текущая привязка и соответствие
проекту Codex. Git не является обязательным условием для чатов или задач.

Причина неудачной проверки показана рядом с её кнопкой и в подробностях журнала.
Сообщение различает ошибку подключения, ключа, привязки, каталога приложения и
ожидания ответа. При неизвестном результате чат или сообщение уже могут существовать;
проверьте журнал и приложение перед новой попыткой.

В **Диагностике** находятся журнал попыток и технический профиль. Каждая строка
журнала — запуск проверки обмена, а не сообщение из переписки. Таблица показывает
начало, результат, проект тестового чата и длительность. Подробности и ссылку на
созданный чат можно раскрыть в строке. Сервер возвращает по 20 попыток на страницу;
кнопки «Назад» и «Далее» открывают старые записи. Обновление сохраняет выбранную
страницу. Счётчики относятся ко всей истории этого подключения и различают
успешные проверки, отсутствие настройки, ошибки и отсутствие ответа.
Завершённая попытка с отсутствующей настройкой не считается успешной проверкой.

**Запросы к моделям** остаются отдельным подразделом: Hub обращается напрямую
к сервису модели, а результат сохраняет в Hub. Вход через ChatGPT и API-ключи
сервисов моделей не подключают управление чатами приложения.

### Если проверка завершилась ошибкой

- **Интерфейс не предоставлен:** подключение MCP уже может работать, но приложение
  ещё не предоставило управление чатами. Для Codex настройте адаптер из его чата.
- **Нужно сохранить настройки / настройки не совпадают:** сохраните адрес,
  протокол и отдельный ключ нужного интерфейса. Сохранение не запускает проверку.
- **Доступ отозван:** восстановите это подключение через приглашение. История
  сохраняется, а старые результаты не подтверждают восстановленный доступ.
- **Ошибка соединения:** убедитесь, что приложение и адаптер запущены. После
  выхода или обновления Codex подключите адаптер из нового чата.
- **Нет ответа до срока:** факт создания или приёма сообщения может быть известен,
  но обратный ответ агента не подтверждён. Проверьте тестовый чат. Новая проверка
  создаст ещё один чат; обновление страницы только читает прежний результат.
- **Настройка или привязка изменилась:** выберите действующий проект и проведите
  новую проверку. Поздний ответ прежнего чата не подтверждает новую привязку.

## Если инструменты Hub не появились в приложении

Запись приложения в Hub подтверждает регистрацию доступа. Чтобы агент мог читать
контекст и сохранять отчёты, само приложение должно успешно загрузить инструменты
MCP. Открытая страница Hub и сохранённые инструкции этого не подтверждают.

Сначала проверьте, что Hub запущен, а в настройках MCP приложения указаны его
текущий адрес и переменная с токеном доступа Hub. Переменная должна быть доступна
процессу приложения. Ключ поставщика модели и ключ управления чатами для этого
не используются. Не публикуйте значение токена в сообщениях или журналах.

Проверяйте результат в штатном MCP-клиенте: в списке должны появиться инструменты
Hub, включая `hub_context` и `hub_report`. Ответ на отдельный HTTP-запрос к Hub
проверяет доступность сервера, но не загрузку инструментов приложением.

## Чаты и связанные задачи

Раздел **Чаты** показывает единый список с поиском и подгрузкой истории, включая
архивные чаты. Внутри чата отдельно показаны связанные задачи и участники.
Дата отражает последнее известное обращение или изменение, а не подтверждение,
что агент сейчас выполняет работу.

Приложение передаёт идентификатор чата, название и поддерживаемую ссылку через
`nativeChat`. Правила подключения требуют передавать доступные данные вместе с
обращениями к Hub и обновлять название после переименования. Hub также сохраняет
подтверждённую связь для последующих обращений в том же сеансе и сообщает агенту,
если данные чата не переданы.
Сохранение чата само по себе не создаёт задачу. При повторном подключении
сведения об одном и том же чате объединяются; исходные события и история
участников сохраняются. Одинаковые идентификаторы разных приложений или их
экземпляров не объединяются.

Кнопка открытия появляется при наличии безопасной ссылки приложения. Для Codex
также используется его локальный каталог метаданных. Открытие существующего
чата по ссылке не требует настроенного интерфейса запуска новых чатов.
Для другого приложения ссылка передаётся явно или формируется по шаблону,
который оно объявило в подключении. Если приложение не передало данные чата,
Hub показывает сеанс и его сохранённые связи с задачами с пояснением о
недоступном открытии. Название задачи не подменяет неизвестное название чата.

## Запуск из Hub

Правила и возможность управлять клиентом учитываются отдельно. Для запуска
требуется настроенный HTTP/MCP-интерфейс и заявленная способность выбирать проект
`projectRouting`. Аргументы операции содержат `$requestId` и `$projectScope`,
`$nativeProject` или `$workspace`. Интерфейс и его отдельный секрет настраиваются
в Hub; произвольные команды и stdin не используются. Наличие MCP для чтения Hub
само по себе не предоставляет API запуска чатов Codex или другого клиента.

Запрос сохраняется до отправки. Конверт содержит requestId, подключение, проект
Hub, ID/ревизию привязки, область клиента, операцию, задачу/этап или объект знаний,
версии входов и фиксированное место результата. Агент читает `hub_launch`, открывает
контекст текущей области и подтверждает запрос через `action="ack"` со своим
настоящим ID чата. При несовпадении области, ревизии или идентичности запрос
отклоняется. Продолжение доступно для завершённого или завершившегося ошибкой
запуска с подтверждённым получением задания в той же задаче, этапе и привязке.
Привязка проверяется перед отправкой и после ответа клиента; её изменение
отменяет запрос и запрещает публикацию результата по старому маршруту.

В карточке задачи или этапа блок **Запустить задачу** предлагает явный выбор
приложения и рабочего пространства, создание чата или продолжение доступного
чата. Агент начинает новую работу после подтверждения задания. Завершение запуска
ссылается на её сохранённый `hub_report` именно этой сессии, задачи и этапа. Анализ
архитектуры и подготовка документа публикуют отдельный Markdown-документ через
`hub_launch(action="complete")` в выбранном проекте с исходной ревизией знаний;
конкурентное изменение вызывает конфликт вместо перезаписи. Фактическая точность
исследования и доказательств остаётся ответственностью агента: квитанция публикации
не объявляет их независимо проверенными.

При неопределённом результате отправки Hub не создаёт второй чат автоматически.
Повтор того же requestId возвращает сохранённую квитанцию Hub. Кнопка
**Повторить тот же запрос** помогает, когда потерян ответ самого Hub; она не
повторяет внешний вызов с неизвестным исходом. В таком случае проверьте приложение
и дождитесь подтверждения агента. Универсальной кнопки восстановления неизвестной
внешней операции сейчас нет. Принятие запроса API,
подтверждение агентом и публикация результата показываются отдельно. Если у клиента
нет документированного настроенного интерфейса запуска, запуск остаётся недоступным.

## Проверка запросов к модели после выхода из Codex

Откройте Hub в обычном браузере. В **Запросах к моделям** сохраните отдельное
подключение и выполните явную проверку. Затем выйдите из Codex, оставив сервер Hub
и браузер запущенными. Запустите новую проверку модели: прежняя квитанция не является
новым запросом. Проверьте время, модель и результат в журнале. Для проверки полного
анализа запустите исследование документа и убедитесь, что результат появился в Hub.

Обычное истечение access-токена ChatGPT обрабатывается автоматическим обновлением.
Hub проверяет срок доступа при подготовке очередного запроса и при необходимости
обновляет авторизацию. Это работает и после выхода из Codex: сервер Hub должен
оставаться запущенным. Для обычного обновления повторный вход не нужен.
Если обновление получено, но его проверка не завершилась, следующий новый запрос
продолжает проверку сохранённого ответа. Потерянный ответ на обновление или
отозванный доступ могут потребовать повторного входа в сервис модели; запуск Codex
или переподключение MCP их не исправляет. Подробнее —
[в справке по авторизации модели](agent-analysis.md). Проверка модели и исследование
могут использовать ваш тариф. Они не создают чат Codex.
