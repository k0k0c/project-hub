# Текущие документы и архивные снимки

Хаб хранит зарегистрированные ссылки на файлы соответствующего проекта. Чтение
текущего документа каждый раз обращается к рабочему файлу. Изменения оригинала
не требуют копирования или синхронизации в Hub.

`source-archive` сохраняет исторические файлы после отделения Hub. Наличие снимка
не меняет выбор текущего документа. Архивы не перезаписываются этим механизмом.
Старые снимки не имеют достоверной даты создания или Git revision: эти сведения
не выдумываются. Версия содержимого — SHA-256 исходных байтов; modifiedAt — только
время изменения файла. Это существующий снимок по пути, не полный каталог всех
версий документа и не автоматическое версионирование каждого сохранения.

Новые самостоятельные вложения любого формата хранятся в существующем Hub CAS
вне checkout продукта. Ссылка `hub-artifact/<descriptor hash>/<name>` выбирает
точную неизменяемую версию. Descriptor содержит стабильный artifact ID, hash и
размер исходных байтов, имя, происхождение, роли и ссылку на предыдущую версию.
Роли могут сочетаться; `evidence` не исключает исходник или fixture из проверок.
`hub_artifact` может сохранить снимок файла проекта, не меняя оригинал и его
участие в build/tests. Продолжение версии требует явного `previous`.

Формат не определяет возможность хранения. Preview adapters проверяют содержимое
отдельно; бинарный файл без адаптера возвращает метаданные и скачивается через
`/api/artifact`. История выбирается точной ссылкой версии, а не режимом archive.
После переноса задачи старые ссылки сохраняют исходный проект; продолжение
версии копирует неизменяемую цепочку CAS в новый проект без изменения aliases
и журналов. Рабочие файлы preview cache с исходным расширением — производные;
при несовпадении hash чтение отказывает, исходные CAS bytes не перезаписываются.

Knowledge backup включает все опубликованные CAS blobs и отдельный manifest
служебных artifact descriptors, сохраняя также неприкреплённые uploads и прошлые
версии. Обычный JSON-артефакт не становится descriptor из-за собственных полей.
Restore проверяет hashes, размеры и цепочку stable ID. Журналы задач сохраняются
общим backup данных проекта отдельно от knowledge snapshot.

## Чтение

- MCP `hub_memory(ref="source:путь")` читает текущий рабочий файл.
- `source-archive:путь` явно читает исторический снимок.
- Ответ включает source (тип, исходный проект, путь, физическое расположение,
  доступность обеих версий), SHA-256 и versionRef. Для последующих страниц следует
  передавать versionRef и offset: изменение версии прерывает чтение, а не смешивает
  фрагменты разных файлов.
- Недоступность текущего файла возвращается явно, с archiveRef при наличии снимка.
  Содержимое архива автоматически не подставляется.
- HTTP `/api/source`, `/api/document`, `/api/evidence`, `/api/log` принимают
  `project`, `path`, `mode=current|archive`; по умолчанию current. `/api/source`
  возвращает метаданные даже для отсутствующего зарегистрированного файла;
  остальные маршруты возвращают 404 при отсутствии выбранной версии.
- Веб-просмотрщик позволяет выбрать текущий документ или архив и показывает
  происхождение. Ссылка на исходный текст сохраняет выбранный режим.

Плашки исходников задачи и доказательств этапа показывают иконку и формат файла:
HTML, Markdown, текст, лог, PDF, офисные документы, таблицы, презентации, данные,
код, архивы, аудио и видео. Неизвестные расширения получают общую иконку файла.
Изображения по-прежнему отображаются отдельной галереей.

HTML/HTM открывается в новой вкладке самостоятельной страницей, без интерфейса
Hub и встроенного просмотрщика. Плашка добавляет `preview=html` к `/api/evidence`
или `/api/artifact`: сервер возвращает исходные байты как `text/html`, без
принудительного скачивания и изменения оформления. Обычная ссылка на оригинал
вложения сохраняет скачивание. Рабочая и архивная версии остаются явным выбором.
Изоляция страницы разрешает встроенные стили и скрипты, но запрещает доступ к
данным Hub и загрузку внешних ресурсов. Для HTML с локальными зависимостями
используется существующий импорт HTML-комплекта в Документацию.

После переноса задачи sourceProject и исходные ссылки сохраняются. Оба режима
разрешают путь внутри исходного проекта, а не ищут одноимённый файл в новом.
Проверки регистрации источника и выхода за границы корня действуют для обоих
режимов. Исторические журналы и сами файлы архива не изменяются.
