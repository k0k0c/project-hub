# Языковые провайдеры исследования

Hub использует стандартный stdio LSP (JSON-RPC с Content-Length). Установка
серверов не встроена: администратор указывает готовый исполняемый сервер.
Проектный код не выполняется Hub. Конкретный сервер может выполнять сборочные
инструменты, поэтому настройки импорта и сборки задаются явно.

Конфигурация: `language-servers.json` в data home каталога Hub, рядом с
`registry.sqlite3`. HTTP и MCP принимают ID провайдера, но никогда команду запуска.

```json
{
  "providers": [{
    "id": "python", "languages": ["python"],
    "command": ["<path>/pyright-langserver", "--stdio"],
    "timeout": 30, "settings": {}, "initializationOptions": {}
  }]
}
```

Это схема конфигурации, а не обещание, что Windows `.cmd` работает без shell:
используйте исполняемый бинарник или явный runtime + JS entrypoint, например
`["<path>/node", "<path>/server.js", "--stdio"]`. Shell не используется.
Плейсхолдер `{root}` выбирает зарегистрированный корень, `{workspace}` —
отдельное служебное состояние для проекта, корня и провайдера.

## Java и JDT

Скачайте совместимый JDT LS с официального сайта Eclipse и распакуйте отдельно.
Создайте конфигурацию штатным помощником:

```powershell
python scripts/knowledge_language.py --jdtls-home <path>/jdtls --java <path>/jdk/bin/java --output <data-home>/language-servers.json
```

Помощник сохраняет остальные провайдеры и по умолчанию отключает автоматическую
сборку и импорт Maven/Gradle. Для существующего Maven-проекта добавьте
`--maven-import`: JDT должен импортировать `pom.xml`, чтобы файлы вошли в
проектный индекс. Автоматическая сборка и импорт Gradle остаются отключены.
Этот помощник только записывает конфигурацию; работу импорта выполняет JDT.
Для unmanaged проекта задайте `settings.java.project.sourcePaths` и зависимости.
Настройка unmanaged source paths не заменяет импорт проекта с `pom.xml`.
Параметры проекта передаются серверу через
`workspace/configuration` и `initializationOptions`.

Выбирайте совместимые версии JDT LS и JDK для вашей среды. Первый
семантический запрос может запустить импорт проекта и подготовку индекса;
последующие запросы используют тот же процесс и кэш Hub. Если серверу или
зависимости требуется другой JDK, подготовка возвращает понятную ошибку
совместимости. Это не гарантирует полную семантику каждого Java-проекта.

Поддерживаются documentSymbol, definition, references, call hierarchy,
implementation и type hierarchy при наличии negotiated capability. Результаты
внешних библиотек/нестандартных URI помечают покрытие частичным. Внутрипроектные
вызовы имеют устойчивую идентичность по URI и позиции; циклы обходятся один раз.
Отмена посылает `$/cancelRequest`; поздний результат не публикуется.

Веб-интерфейс отправляет `provider=auto`; Hub выбирает источник по виду
символа, языку и возможностям сервера. Явный ID провайдера остаётся доступным
для программных клиентов. Пустые ответы при диагностике «non-project file»,
«only syntax errors» или ошибке семантики помечаются `partial`; предупреждение
другого файла не делает текущий запрос неполным, а очищенная диагностика не
остаётся навсегда активной. Такой результат не используется как полный кэш.

## Другие языки

Python, TypeScript и C++ используют тот же адаптер и свои серверы. Установка,
версия runtime, classpath/venv/tsconfig/compile_commands остаются особенностями
провайдера. Общий протокол не гарантирует одинаковый набор операций или штатную
установку для любого языка. Неизвестные возможности явно показываются как
неподдерживаемые; новый язык не требует новой схемы навигации.

[Спецификация LSP](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/)
и [JDT LS](https://github.com/eclipse-jdtls/eclipse.jdt.ls).
