# Пользовательские правила Project Hub

## Язык интерфейса и справки

Пиши интерфейс, справку и пользовательскую документацию для человека, который
может работать с Codex без знания внутреннего устройства Hub. Начинай раздел
с назначения и главного действия; подробности раскрывай постепенно. Объясняй
незнакомые термины, не смешивай русский и английский в обычных фразах, не
дублируй инструкции и не показывай служебные ID без практической пользы.
Сохраняй точные имена API и файлов в технических деталях. Заголовки цитируемой
инструкции должны быть ниже заголовков страницы. Используй полные естественные
формулировки, пригодные для перевода; объяснение для человека и контракт для
агента должны быть разделены. Не обещай ещё не реализованную поддержку языков.

Применяй эти правила вместе со встроенным skill `project-hub`, когда работаешь с
подключённым Project Hub. Эти предпочтения относятся только к работе с Hub.

## Когда учитывать работу

Для реализации, исправления, исследования, ревью и подготовки документации
найди подходящую задачу Hub или создай её, если подходящей нет. У каждой задачи
должны быть видимый этап и результат. Короткий ответ по уже известному контексту
не требует отдельной новой задачи; существенные новые выводы добавь в текущую.

Перед содержательной работой над этапом сообщи `hub_begin` с его ID, своей
проверенной identity и конкретными ресурсами. Открытая карточка задачи ещё не
означает, что работа началась. Первичное чтение инструкций, контекста и выбор
задачи допустимы до регистрации начала.

## Работа и параллельные изменения

Указывай файлы, каталоги и общие ресурсы, которые действительно затрагиваешь.
Обновляй сведения при изменении области работы. Сообщай о реальном ожидании
внешней зависимости и возобновлении; не используй ожидание как разрешение на
запись. Уведомление о пересечении ресурсов — повод согласовать работу через
возможности Codex. Оно само по себе не разрешает отправлять сообщения другим
чатам и не даёт полномочий редактировать чужую работу.

## Проверки и завершение

Выбирай проверки по инструкциям и профилям конкретного проекта. Завершение
этапа само по себе не является причиной полного прогона. Сначала закончи
согласованный объём изменений, затем выполни необходимые проверки.

Сохраняй фактический результат и доказательства через `hub_report`.
Завершай этап, когда его условия выполнены; задачу закрывай после выполнения
критериев и требуемых проверок. Stop и SessionEnd описывают наблюдаемую
активность чата, а не завершённость работы или задачи.

## Недоступность и границы

При недоступном Hub продолжай разрешённую пользователем работу и укажи пробел
учёта при передаче результата. Hub не управляет разрешениями Codex и не заменяет
инструкции проекта. Не создавай обходные базы, журналы или механизмы доступа.
